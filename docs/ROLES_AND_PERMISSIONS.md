# STRUCTURA — Ролі та права

Джерело істини — БД (RLS + RPC). UI лише відображає можливості. Правила реалізовані в SQL; тести
`supabase/tests/rls_isolation.sql` покривають більшість, але **не всі** сценарії. Не покриті автоматичними тестами:
дії від імені ролі `admin` (зокрема «admin не може призначити/змінити admin»), вихід учасника з компанії самостійно,
сценарії `object_manager` не від створювача, зміна/видалення учасників обʼєкта (`update_/remove_object_member`).

> **Власник компанії ≠ власник нерухомості.** `company_role = owner` — власник підрядної компанії.
> `object_role = property_owner` — замовник/власник квартири чи будинку на конкретному обʼєкті.

## 1. Рівні

| Рівень | Ролі | Де зберігається |
|---|---|---|
| Платформа | `super_admin`, `user` | `profiles.platform_role` (змінити через API неможливо) |
| Компанія | `owner`, `admin`, `foreman`, `senior_worker`, `worker`, `surveyor`, `designer`, `tool_keeper` | `company_members` |
| Обʼєкт | `object_manager`, `foreman`, `worker`, `surveyor`, `designer`, `property_owner`, `intermediary` | `object_members` |

Одна людина може мати різні ролі на різних обʼєктах; на одному обʼєкті — одну роль (D-006).

`super_admin`: роль збережена, але **на Етапі 1 не дає жодного неявного доступу** до даних компаній (D-007).

## 2. Видимість даних

| Хто | Компанія | Обʼєкти | Учасники компанії | Запрошення | Журнал |
|---|---|---|---|---|---|
| owner / admin компанії | своя | **усі** обʼєкти компанії | так | так | так |
| інша роль компанії (foreman, worker, …) | своя | лише обʼєкти, де є в `object_members` | так | ні | компанійські + доступні обʼєкти |
| зовнішній учасник обʼєкта (`property_owner`, `intermediary`) | бачить компанію (назва/контакти) | лише свої обʼєкти | **ні** | ні | лише події своїх обʼєктів |
| сторонній | нічого | нічого | ні | ні | ні |

Профілі: бачите себе, людей зі спільної компанії/обʼєкта; owner/admin бачать зовнішніх учасників обʼєктів своєї компанії;
учасники обʼєкта бачать керівництво (owner/admin) компанії-підрядника.

## 3. Дії

| Дія | Хто може |
|---|---|
| Створити компанію | будь-який автентифікований (стає `owner`) |
| Редагувати дані компанії (назва, контакти…) | owner, admin |
| Змінювати `owner_id`, статус компанії | ніхто через API |
| Створити обʼєкт | owner, admin, foreman компанії |
| Редагувати/архівувати обʼєкт | owner, admin; `object_manager` і `foreman` цього обʼєкта |
| Видалити обʼєкт | ніхто (архівування) |
| Призначити прораба обʼєкта | той, хто може редагувати обʼєкт; прораб = member компанії з роллю owner/admin/foreman; автоматично стає учасником обʼєкта |
| Додати учасника компанії | лише через запрошення з роллю компанії: owner (будь-яка, крім owner), admin (крім admin/owner) |
| Змінити роль учасника компанії | owner (будь-яку, крім owner); admin — лише не-admin; себе — ніхто; роль `owner` — ніхто |
| Видалити учасника компанії | owner/admin за тими ж правилами; учасник може вийти сам (крім owner) |
| Додати учасника обʼєкта (внутрішні ролі) | хто керує обʼєктом; `object_manager` — лише owner/admin |
| Запросити зовнішніх (`property_owner`, `intermediary`) | хто керує обʼєктом, через `create_invitation` |
| Запросити з роллю `object_manager` | owner, admin |
| Відкликати / повторно видати запрошення | ті, хто мав би право його створити |
| Прийняти запрошення | лише користувач із **підтвердженим** email, що збігається з адресою запрошення |

## 4. Не перевірено / відкладено

- Права `senior_worker`, `surveyor`, `designer`, `tool_keeper` у модулях Measure/Tools/Workforce — визначаться на їхніх етапах.
  Зараз ці ролі лише зберігаються й дають видимість компанії та призначених обʼєктів.
- Передача володіння компанією — не реалізована.
